# 게임플레이 깊이 설계 (A)

## 배경

현재 AI(`aiTakeTurn`)는 가능한 모든 (손패, 바닥) 조합 중 점수가 가장 높은
캡처 하나만 고르는 단순 탐욕 로직이고, 승패는 순수 이진 값(스트레이트 완성
여부)이라 판 중간의 밀고 당기는 긴장감이 약하다. 이 문서는 세 가지를 다룬다:
(1) 카드 랭크 체계를 1~10에서 전통 카드게임 방식의 13랭크(A,2~10,J,Q,K)로
개편, (2) 색상 무관 특수카드("프리즘카드") 도입, (3) AI 난이도 단계,
(4) 연속 캡처 콤보 보너스.

(1)과 (2)는 이번 대화에서 여러 차례 확인을 거쳐 최종 확정된 규칙이며, 아래
내용은 기존 함수(`isValidEat`, `findStraight`, `pointValue`, `buildDeck`)의
정확한 현재 동작을 코드로 직접 확인하고 그 위에 설계했다.

## 1. 카드 랭크 체계 개편 (1~10 → 13랭크)

### 현재 동작 (변경 전, 코드 확인 완료)

- `isValidEat` ([index.html:677](../../../index.html)): 바닥 A(1)는 손패 10
  으로만, 손패 A(1)는 바닥 10을 캡처 가능. 그 외엔 동색+손패값≥바닥값, 같은
  숫자면 색 무관.
- `findStraight`: `start`가 1~6을 돌며 `[start, start+4]` 6개 구간만 검사.
  A는 값 1로만 취급되고 10과 이어지는 상위 구간(`6-10`)에는 A가 관여하지
  않음 — 즉 지금은 `6,7,8,9,10`만 상위 스트레이트고 `6,7,8,9,A`는 인정 안 됨.

### 변경 후 규칙

**랭크값**: A=1, 2~10=그대로, J=11, Q=12, K=13.

**`isValidEat` — "10"을 "K"로 교체**:
```
hand.isJoker            → true (와일드, 기존 동일)
floor.isJoker            → hand.value === 1 (A만 가능, 기존 동일)
hand.value === floor.value → true (색 무관, 기존 동일)
!hand.isPrism && !floor.isPrism && hand.color !== floor.color → false
floor.value === 1 (A)    → hand.value === 13 (K)   // 기존 "10" 자리
hand.value === 1 && floor.value === 13 (K) → true  // 기존 "10" 자리
그 외                     → hand.value >= floor.value
```
(프리즘카드 관련 조건은 2절에서 설명)

**`findStraight` — 전통 포커식 10구간, 랩어라운드 없음**:
가능한 구간은 `start`를 1~10으로 돌며 `[start, start+4]`를 확인하되, 값이
13(K)을 넘어가면(=14) 실제 조회는 값 1(A)로 한다. 이렇게 하면 정확히
아래 10구간만 유효해진다:
```
A-2-3-4-5, 2-6, 3-7, 4-8, 5-9, 6-10, 7-J, 8-Q, 9-K, 10-J-Q-K-A
```
`K-A-2-3-4` 같은 랩어라운드(K 다음 바로 A-2-3로 이어지는 것)는 전통 룰대로
인정하지 않는다.

**`pointValue`**: J=11, Q=12, K=13 반환하도록 추가 (AI 탐욕 비교 및 콤보/특수
카드 우선순위 계산에 쓰임).

**`buildDeck`**: 색상당 10장 → 13장으로 확장(J,Q,K 3장씩 추가). 색상 수는
인원수에 따라 2~4이므로 총 카드 수도 그만큼 늘어난다.

**⚠️ 미확정 사항 (구현 시 플레이테스트 필요)**: 카드 수가 색상당 +3장(전체
+6~+12장) 늘어나면 한 판의 길이, 중앙덱 소진 타이밍, 초기 딜 매수 밸런스가
달라진다. 정확한 초기 손패 수를 그대로 둘지 늘릴지는 이번 설계에서 정하지
않았고, 구현 단계에서 실제로 돌려보고 조정한다.

## 2. 프리즘카드 (색상 무관 특수카드)

- **랭크 7 고정, 2장**. 기존에 색상별로 있던 7(인원수만큼, 2~4장)은 그대로
  두고 프리즘 2장을 **추가**한다 (교체 아님). 인원수에 따라 색상 수가
  바뀌어도 프리즘 수량은 항상 2장으로 고정 — 어떤 색의 7을 빼야 할지 정할
  필요가 없어 설계가 인원수에 무관하게 일관됨.
- 데이터 모델: 카드 객체에 `isPrism: true`, `value: 7`, `color: null` 부여.
- **캡처 규칙**: "같은 숫자면 색 무관 캡처" 규칙이 이미 있어서, 바닥의
  프리즘카드든 일반 7이든 손패 7 아무거나로 캡처 가능 — 별도 규칙 불필요.
  손패에 프리즘카드가 있을 때 다른 랭크를 공격하는 경우엔 위 `isValidEat`
  수정안의 `!hand.isPrism && !floor.isPrism` 조건 덕분에 색 검사를 건너뛰고
  랭크 비교만 적용된다 (손에 있든 바닥에 있든 색이 항상 "매치"로 취급).
- **스코어링**: `findStraight`가 `vals`를 만들 때, 현재는
  `if(!c.isJoker && c.color===color) vals[c.value]=true;` 인 부분을
  `if(!c.isJoker && (c.color===color || c.isPrism)) vals[c.value]=true;`
  로 바꿔서, 점수더미의 프리즘카드가 **검사 중인 모든 색의 7 자리에
  동시에 카운트**되게 한다. 조커처럼 완전 와일드(아무 자리나 채움)가
  아니라 "랭크 7은 확정, 색만 무관"이라는 점이 조커와의 차별점.
- 밸런스 메모: 프리즘 포함 랭크 7은 다른 랭크보다 덱에 2장 더 많아 캡처
  경쟁이 잦아진다 — 의도된 긴장감 포인트로 간주하고 그대로 둠.

## 3. AI 난이도 단계

인원 선택 화면(`screen-count`)에 쉬움/보통/어려움 pill 추가, 기본값 보통,
localStorage로 마지막 선택 기억. `aiTakeTurn`의 캡처 후보 선택 로직만
난이도별로 분기한다 (드로우/조커 리필 폴백 로직은 공통 유지).

- **쉬움**: 현재 그대로 — 가능한 캡처 중 `pointValue` 최고값 선택, 전략 없음.
- **보통**: 쉬움 로직에 가중치 추가 — 자신의 점수더미에서 이미 진행 중인
  색상의 스트레이트 구간을 이어가는 캡처를 우선 (예: 이미 핑크 3,4,5를
  갖고 있으면 핑크 2나 핑크 6 캡처를 다른 색 고점수 캡처보다 우선).
- **어려움**: 보통 로직 + 상대 견제 — 캡처 후보 각각에 대해 "이 카드를 두면
  다음 상대 턴에 상대가 자기 스트레이트를 진행/완성시킬 수 있는가"를
  계산해 방해 캡처에 가중치 부여. 조커는 손패 6장 이상 강제 리필 조건에서만
  소모(기존 동일)하되, 자기 스트레이트의 남은 빈 자리를 정확히 채울 수
  있는 상황이면 리필보다 보유를 우선. **프리즘카드는 항상 최우선 고려
  대상**으로 취급 — `pointValue`상 J/Q/K보다 낮아도(7) 모든 색에 동시
  기여하는 전략적 가치가 크므로 어려움 AI는 이를 가중치에 반영한다.

## 4. 연속 캡처 콤보 보너스

- 턴 구조가 "턴당 액션 1개(캡처 또는 드로우)"이므로, "연속"은 자기 턴
  기준 드로우 없이 캡처가 몇 턴째 이어졌는지로 정의한다.
- `player.captureStreak` 카운터 신설: 캡처 성공 시 +1, 드로우/패스 시 0
  으로 리셋.
- **streak이 2에 도달한 턴에 한해**, 그 턴에 한 번 더 캡처를 시도할 수 있는
  보너스 찬스를 부여한다 (유효한 캡처가 남아있을 때만). 보너스는 턴당
  최대 1회 — 무한 연쇄는 아님 (밸런스 안전장치).
- 보너스 발동 시 "🔥 콤보! 보너스 캡처" 토스트/이펙트로 시각 피드백.

## 범위 밖 (이번 설계에서 제외)

- 앞서 논의한 10개 특수카드 아이디어(역전카드, 도둑카드, 폭탄카드,
  더블캡처카드, 스왑카드, 셔플카드, 타임어택카드, 미러카드, 다이스카드,
  프리즘카드 이전 버전) 중 **프리즘카드만 이번 스펙에 확정**되었다. 나머지는
  아직 채택되지 않았고, 원하면 별도 서브프로젝트로 다시 다룬다.

## 성공 기준

- 전통 카드게임에 익숙한 플레이어가 낯설지 않게 스트레이트 규칙을 이해한다.
- 프리즘카드가 등장하는 판마다 캡처 경쟁의 긴장감이 눈에 띄게 올라간다.
- 난이도를 올릴수록 AI를 이기기 실제로 더 어려워진다 (쉬움 대비 어려움에서
  플레이어 승률이 체감 가능한 수준으로 낮아짐).
- 콤보 보너스가 "한 방에 게임이 끝나는" 수준으로 과하지 않으면서도 턴마다
  캡처를 이어가려는 동기를 만든다.
