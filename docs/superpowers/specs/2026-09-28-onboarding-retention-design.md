# 온보딩/리텐션 설계 (D)

## 배경

스트레이트!는 계정 시스템이 없는 단일 파일 브라우저 게임으로, 모든 상태는
클라이언트별 `localStorage`에만 존재한다. 현재 신규 플레이어는 아무 안내 없이
바로 모드 선택 화면에 던져지고(정적 "규칙 보기" 버튼만 존재), 재방문을 유도할
장치가 전혀 없다. 이 문서는 두 가지를 다룬다: (1) 선택적 튜토리얼, (2) 누적
플레이 기반 캐릭터/카드뒷면 잠금해제 시스템.

## 1. 튜토리얼 (정적 캐러셀)

### 트리거
- 시작 화면(`screen-start`)에 새 버튼 `📖 튜토리얼` 추가. 기존 "게임 시작"
  버튼 및 설정 아이콘 옆에 배치.
- 완전히 선택적 — 첫 실행 자동 노출이나 강제 게이팅 없음. 언제든 재방문 가능.

### 콘텐츠 구조
6장짜리 모달 캐러셀 (좌우 화살표 + 하단 도트 인디케이터):
1. 목표 — 스트레이트(같은 색 1~10 스트레이트) 완성이 승리 조건임을 소개
2. 드로우/캡처 기본 — 턴마다 바닥 카드를 가져오거나(캡처) 중앙 덱에서 뽑는다
3. 색상+숫자 매칭 캡처 — 손패 카드로 바닥의 같은 색+같은 숫자 카드를 가져가는 규칙
4. 조커 사용법 — 조커로 어떤 바닥 카드든 가져올 수 있음
5. 바닥 조커 특수 규칙 — 바닥에 조커가 있을 때는 손패의 1(A)로만 가져올 수 있음
6. 승리 조건 — 스트레이트 완성 시 즉시 승리, 완성 못하면 덱 소진 후 무승부 판정

각 슬라이드는 실제 `.card` 엘리먼트를 작게 재사용해 예시를 시각적으로 보여준다
(새 이미지 에셋 불필요). 마지막 슬라이드의 "시작하기" 버튼은 모드 선택 화면으로
이동한다.

### 구현 메모
- 새 게임 상태/로직 불필요 — 순수 UI 모달. 기존 `openSettingsModal()` 같은
  모달 패턴을 그대로 따라 구현 가능.
- 개발 리스크 낮음, 새 서브시스템 없이 기존 코드베이스에 얹는 수준.

## 2. 캐릭터/패턴 잠금해제 시스템

### 데이터 모델
```js
// localStorage key: "straightStats"
{ wins: number, games: number }

// localStorage key: "straightUnlocks"
["avatar:megablock", "pattern:diagonal", ...]  // 해금된 item id 배열
```

- `games`는 로컬 플레이어가 참여한 게임(솔로 AI전 + 온라인전 모두 포함)이
  끝날 때마다 1 증가.
- `wins`는 로컬 플레이어가 승리했을 때만 1 증가.
- 훅 지점: `showWinScreen(player, straight)` 호출부 — `player`가 로컬
  클라이언트(`getClientId()`)와 일치하는지 확인 후 카운트 증가. 무승부
  (`declareDraw()`)는 games만 증가, wins는 증가 없음.

### 해금 판정
- 각 마일스톤은 `{winsRequired, gamesRequired, reward: {kind, id}}` 형태.
- **승리 수 OR 누적 게임 수 중 먼저 도달하는 쪽으로 해금** — 승률이 낮은
  플레이어도 꾸준히 플레이하면 소외되지 않도록 함.
- 게임 종료 시점(승리/무승부 모두)마다 전체 마일스톤 목록을 순회하며 아직
  `straightUnlocks`에 없는 항목 중 조건 충족한 것을 해금 처리.
- 해금 발생 시 승리/결과 화면 위에 토스트 배너 표시: `🎉 새 아바타 해금: OOO`
  (또는 새 카드 뒷면).

### 콘텐츠 배분
- 카드 테마 3종은 계속 전부 무료 (구조적 요소라 잠금 대상에서 제외).
- **아바타 8종 + 카드 뒷면 패턴 7종만** 마일스톤 대상 (총 15개 잠금 슬롯).
- 스타터: 아바타 2개 + 패턴 2개는 항상 해금 상태로 시작.
- 나머지 6아바타 + 5패턴을 점점 벌어지는 임계값에 순차 배정:
  승수 1 / 2 / 3 / 5 / 8 / 12 / 18 / 25 / 35 / 50, 게임수는 각 항목당
  승수 임계값의 약 3배 (예: 승수 5 항목은 게임수 15로도 해금 가능).
  정확한 순서(어느 아바타/패턴이 몇 번째인지)는 구현 단계에서 확정.

### 기존 플레이어 보호 (마이그레이션)
- 이 기능이 배포되는 시점에 이미 `straightNickname` 또는
  `straightCardTheme` 같은 기존 localStorage 키가 존재하면 = 이전부터
  플레이한 흔적으로 간주하고, `straightUnlocks`를 **전체 해금 상태**로
  초기화한다.
- 완전히 새로 설치한 사람만 잠금 상태로 시작한다.
- 목적: 지금까지 자유롭게 쓰던 아바타/패턴을 배포 시점에 갑자기 빼앗는
  경험을 방지.

### UI 변경 지점
- 아바타 피커 (`screen-avatar`): 잠긴 아바타는 흐릿하게 표시 + 자물쇠 아이콘,
  선택 불가. 몇 승/몇 판 남았는지 툴팁으로 안내.
- 설정 모달의 카드 뒷면 그리드 (`swatch-grid` / `.pattern-swatch-btn`,
  이번 세션에서 이미 3열 그리드로 압축됨): 잠긴 패턴도 동일하게 흐릿 표시 +
  자물쇠.

## 범위 밖 (이번 설계에서 제외)

- 일일 도전과제 (daily challenge) — 계정 없는 로컬 전용 구조에서 "오늘"
  리셋 로직이 기기/브라우저 전환 시 부자연스러워 이번 스코프에서 제외.
  향후 별도 서브프로젝트로 재검토 가능.
- 아바타/패턴 외 콘텐츠(BGM 트랙 등)의 잠금해제 — 스코프 확장 필요 시 후속.

## 성공 기준

- 신규 플레이어가 규칙을 몰라서 이탈하는 케이스가 튜토리얼로 줄어든다.
- 기존 플레이어는 배포 후에도 지금 쓰던 아바타/패턴을 그대로 쓸 수 있다.
- 새로 설치한 플레이어는 플레이할수록 새 콘텐츠가 열리는 경험을 한다.
